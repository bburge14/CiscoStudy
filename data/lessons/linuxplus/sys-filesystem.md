# The Filesystem Hierarchy, Files & Links

Everything in Linux hangs off a single tree. There are no drive letters; a storage
device becomes usable only when it is *mounted* onto a directory somewhere under
the root, `/`. Knowing where things live — and the handful of commands that create,
inspect and link files — is the foundation every other skill in this track builds
on.

## One tree, rooted at `/`

The layout is standardized by the **Filesystem Hierarchy Standard (FHS)**, so the
same directories mean the same thing across distributions. The ones the exam
expects you to recognize:

| Path | What lives there |
|------|------------------|
| `/` | The root of the whole tree; everything descends from here |
| `/bin`, `/sbin` | Essential user and system binaries (on modern distros, symlinks into `/usr`) |
| `/etc` | System-wide configuration — text files, no binaries |
| `/home` | Ordinary users' home directories (`/home/jordan`) |
| `/root` | The root user's home directory (not the same as `/`) |
| `/var` | Variable data that grows: logs (`/var/log`), mail, spools, caches |
| `/tmp` | Temporary files, world-writable, often cleared on reboot |
| `/usr` | Read-only user programs, libraries and docs (`/usr/bin`, `/usr/lib`) |
| `/opt` | Optional third-party software bundles |
| `/boot` | Kernel image, initramfs and the bootloader's files |
| `/dev` | Device nodes (`/dev/sda`, `/dev/null`) |
| `/proc`, `/sys` | Virtual filesystems exposing kernel and process state |
| `/mnt`, `/media` | Mount points for temporary and removable media |

> `/proc` and `/sys` are not on disk. They are generated by the kernel in memory,
> so a file like `/proc/cpuinfo` is really a live view into the running system.

### Absolute vs. relative paths

An **absolute path** starts at the root and begins with `/` — it means the same
thing from anywhere: `/var/log/syslog`. A **relative path** is interpreted from
your current directory (`cd`, shown by `pwd`). Two shorthands matter: `.` is the
current directory and `..` is the parent. So `cd ../config` walks up one level and
into `config`.

## Reading `ls -l`

`ls -l` is the single most important listing command. Learn every field:

```
-rw-r--r--  1  root  staff  1420  Nov 13 09:14  hostname
[1]         [2] [3]   [4]    [5]   [6]           [7]
```

1. **Type + permissions.** The first character is the file type; the next nine are
   the owner/group/other permission bits.
2. **Link count** — how many hard links point at this inode.
3. **Owner** (user).
4. **Group**.
5. **Size** in bytes (add `-h` for human-readable units like `1.4K`).
6. **Modification time.**
7. **Name.**

That leading type character is worth memorizing:

| Char | Meaning |
|------|---------|
| `-` | Regular file |
| `d` | Directory |
| `l` | Symbolic link |
| `b` | Block device (disk) |
| `c` | Character device (terminal) |
| `p` | Named pipe (FIFO) |
| `s` | Socket |

## Moving around and manipulating files

The everyday verbs:

- `cp source dest` copies; `cp -r` recurses into directories; `cp -a` archives
  (preserves permissions, timestamps and links).
- `mv` both moves and renames — there is no separate rename command.
- `rm` deletes; `rm -r` recurses; `rm -f` forces. There is no undo and no recycle
  bin, so treat `rm -rf` with respect.
- `mkdir -p a/b/c` creates a whole path, making parents as needed.
- `touch file` creates an empty file or updates an existing file's timestamp.

To inspect contents without an editor: `cat` dumps a whole file, `less` pages
through it interactively, and `head`/`tail` show the first or last lines
(`tail -f` follows a growing log live). `stat` reveals the inode number, exact
size, permission bits and the three timestamps (access, modify, change), while
`file` guesses a file's type by inspecting its contents rather than its name.

### Finding things

- `find /etc -name "*.conf" -type f` walks the tree in real time, matching by
  name, type, size, owner or modification time — slow but always current.
- `locate sshd_config` consults a prebuilt database (refreshed by `updatedb`), so
  it is near-instant but only as fresh as the last database build.
- `du -sh /var/log` sums the space a directory consumes; `df -h` shows free space
  per mounted filesystem.

### Globbing

The shell expands wildcards *before* the command runs: `*` matches any run of
characters, `?` matches exactly one, and `[abc]` matches one character from the
set. So `rm report_202[0-3].csv` deletes four specific files. This is shell
expansion, not a feature of `rm`.

## Hard links vs. symbolic links

A file's real identity is its **inode** — a numbered record holding the metadata
and the pointers to its data blocks. A filename is just a directory entry pointing
at an inode.

- A **hard link** (`ln target linkname`) is a second directory entry pointing at
  the *same inode*. Both names are equal; the data survives until the link count
  reaches zero. Hard links cannot cross filesystems and cannot point at
  directories.
- A **symbolic (soft) link** (`ln -s target linkname`) is a tiny separate file
  that stores a *path* to the target. It can cross filesystems and point at
  directories, but it breaks if the target is moved or deleted (a "dangling"
  link).

```
$ ln -s /opt/app/v2.3/bin/app /usr/local/bin/app   # symlink that can be repointed
$ ls -l /usr/local/bin/app
lrwxrwxrwx 1 root root 24 Nov 13 09:20 /usr/local/bin/app -> /opt/app/v2.3/bin/app
```

> Rule of thumb: use a **symlink** when you need to span filesystems, link a
> directory, or keep a stable name you can repoint later (classic `current ->
> v2.3` pattern). Use a **hard link** only within one filesystem when you want two
> equal names for identical data.

## Archiving and compression

Packaging files for transfer or backup uses `tar`, often combined with a
compressor:

- `tar -czf backup.tar.gz /etc` creates (`c`) a gzip-compressed (`z`) archive to a
  file (`f`).
- `tar -xzf backup.tar.gz` extracts it; add `-v` for verbose and `-t` to list
  contents without extracting.
- Standalone compressors `gzip`, `bzip2` and `xz` trade speed for ratio, `xz`
  usually squeezing hardest.

## Exam focus

- The tree is rooted at a single `/`; storage is attached by *mounting*, not by
  drive letters. Know the FHS meanings, especially `/etc` (config), `/var`
  (logs/variable data), `/boot`, `/proc` and `/sys` (virtual, in-memory).
- In `ls -l`, read the fields in order: type+permissions, link count, owner,
  group, size, mtime, name. The first character gives the type — `d` directory,
  `l` symlink, `-` regular file.
- `cp -r` recurses, `cp -a` preserves everything; `mv` renames; `rm -rf` is
  irreversible. `mkdir -p` makes parent directories.
- `find` searches live and flexibly; `locate` is fast but database-backed and may
  be stale. `stat` shows inode/timestamps; `df` is free space, `du` is usage.
- **Hard link** = same inode, same filesystem, no directories, created with `ln`.
  **Symbolic link** = stores a path, crosses filesystems, links directories,
  created with `ln -s` — and can dangle if the target disappears.
- Wildcards (`*`, `?`, `[...]`) are expanded by the *shell* before the command
  sees them.
