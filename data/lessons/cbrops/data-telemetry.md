# Monitoring Data Types & Network Telemetry

Security monitoring is only as good as the data you collect, and not all data is
equal. Full packets tell you *everything* but cost a fortune to store; a flow
record tells you *who talked to whom* for almost nothing. A good analyst knows
which data type answers which question — and which telemetry to reach for when
full capture isn't an option. That trade-off is the heart of this lesson.

## The categories of monitored data

Network security monitoring (NSM) sorts collected data into a handful of
categories. Each sits at a different point on the **detail vs. cost** curve.

> **Full packet capture** records every byte, including payload. **Session data**
> summarizes a conversation (the metadata of a flow) with no payload.
> **Transaction data** records application request/response pairs. **Alert data**
> is what a sensor flags as suspicious. **Statistical data** is aggregated,
> derived numbers. **Metadata** is "data about data."

| Data type | What it contains | Analyst uses it to… | Cost |
|-----------|------------------|---------------------|------|
| **Full packet capture (PCAP)** | Every byte on the wire, headers *and* payload | Reconstruct a transferred file or read an exact exchange | Very high (storage-heavy) |
| **Session data** | 5-tuple, byte/packet counts, start/stop times — no payload | See who talked to whom, when, how much | Very low |
| **Transaction data** | App-layer request/response (an HTTP GET → 200, a DNS query → answer) | Follow what applications actually did | Moderate |
| **Alert data** | Sensor-generated hits (an IDS rule match) | Know what a tool already judged suspicious | Low |
| **Statistical data** | Aggregated metrics (top talkers, bytes/hour, peaks) | Spot anomalies and trends over time | Low |
| **Metadata** | Descriptive fields about other data (file author/size, email headers) | Get context without reading content | Low |

The defining trade-off: **full packet capture** is the richest evidence you can
have — you can carve out the actual malware binary an attacker transferred — but
its **storage cost** means you usually cannot keep it for long. **Session data**
holds no payload yet survives for months cheaply, which is why it is the
backbone of long-term network visibility.

A worked example to cement it: suppose an internal host beacons to a suspicious
server every night.

- **Session/flow data** shows the repeating connection and the volume — enough to
  flag beaconing or a 40 GB overnight upload even though it holds *no payload*.
- **Transaction data** shows the specific URLs requested and the responses.
- **Full packet capture**, if you have it for that window, lets you extract the
  exact bytes to confirm what was stolen.

## Network telemetry: seeing traffic at scale

Because full capture doesn't scale, SOCs lean on lighter-weight telemetry.

### NetFlow and flow records

**NetFlow** (and its standardized cousin IPFIX) is the workhorse of scalable
visibility. A device exports a **flow record** for each conversation it sees.

> A standard **NetFlow record** reports the **source and destination IP and
> port, the protocol, byte and packet counts, and timestamps** for a flow — but
> **no payload**. It is session data generated by routers and switches.

That sounds minimal, but it is powerful. The byte counts and endpoints alone can
reveal an abnormally large outbound transfer to an unknown destination — a
classic data-exfiltration indicator — and months of flow history fit where days
of full packets would not. NetFlow answers *who, when, how much*; it cannot
answer *what exactly was in the payload*.

One practical wrinkle: on high-speed links, devices often export **sampled**
flows (one in every N packets) to keep up, so flow byte counts can be estimates
rather than exact totals. **IPFIX** is the IETF-standardized, vendor-neutral
successor to Cisco's original NetFlow and carries the same idea in an extensible
format. Either way, the analyst's mental model is unchanged: a flow record is a
cheap, long-lived summary of a conversation with no payload.

### Packet capture tools

When you *do* want the payload, you capture packets. **tcpdump** is the standard
command-line tool: it reads traffic off an interface and can write it to a
**.pcap** file for later analysis in a tool such as **Wireshark**. Keep the
mental split clear — **tcpdump/PCAP = full content, heavy; NetFlow = flow
summary, light.**

### Firewalls and content filtering

Perimeter devices also generate and shape telemetry:

- **Next-generation firewall (NGFW)** — beyond a traditional stateful firewall's
  port/protocol filtering, an NGFW adds **application awareness**, an
  **integrated IPS**, and **deep packet inspection**. Crucially, it identifies
  an application by *inspecting its content and behavior*, not just the port — so
  an app hiding on a non-standard port is still recognized.
- **Web content filtering (secure web gateway)** — blocks users from reaching
  known-malicious or policy-prohibited sites by **URL category and reputation**.
- **Email content filtering (secure email gateway)** — scans inbound mail and
  **strips malicious attachments** and quarantines phishing and spam before it
  reaches the inbox.

Each of these both *enforces* policy and *emits logs* that feed the SIEM — so a
content filter is simultaneously a control and a source of monitoring data.

## Choosing the right data

Think of it as asking the cheapest question that will do:

1. *Did two hosts talk, and how much?* → **session / NetFlow** (cheap, long
   retention).
2. *What did the application actually request?* → **transaction data**.
3. *What exactly was transferred, byte for byte?* → **full packet capture** (if
   you have it for that window).
4. *What did a sensor already flag?* → **alert data**, then pivot to the above.

That discipline keeps storage sane while still letting you reconstruct an
incident when you must.

## Exam focus

- Know the six data types cold: **full packet capture** (every byte, payload
  included, storage-heavy), **session** (flow summary, no payload, cheap/long),
  **transaction** (app request/response), **alert** (sensor hits), **statistical**
  (aggregated metrics), **metadata** (data about data).
- The main **drawback of full packet capture** is **storage** — you can't keep it
  long. Session data's advantage is low cost and long retention with no payload.
- A **NetFlow record** = src/dst IP + port, protocol, byte/packet counts,
  timestamps; **no payload**. It is a form of session data and can reveal large
  exfil transfers by volume alone.
- **tcpdump** captures packets to a **.pcap** for Wireshark; it is full-content
  capture, unlike NetFlow.
- **NGFW** adds application awareness, integrated IPS, and deep inspection and
  IDs apps by content, not port. **Web/email content filtering** block malicious
  sites and strip malicious mail.
